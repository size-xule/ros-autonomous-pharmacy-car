# ADR-0001：用 ROS 2 Lyrical，不降级到 Humble

- **状态**：已采纳
- **日期**：2026-11（记录于 2026-11-13）
- **决策者**：cxy、xl

---

## 背景

厂商交付的镜像自带 **Ubuntu 26.04.1 + ROS 2 Lyrical**（`/opt/ros/lyrical`，`ros-lyrical-ros-base 0.13.0-3resolute`）。

而整个 ROS 2 生态的**教程、问答、第三方包**绝大多数围绕 **Humble（22.04）** 或 **Jazzy（24.04）**。
接手的人第一个念头通常是："降级到 Humble，这样网上资料多。"

## 决策

**保持 Lyrical，不降级。**

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| **降级到 Humble** | ① 厂商镜像里 **334 个 `ros-lyrical-*` 包**、`/opt/eprobot_ws` 的 install 树、任务层二进制（`f1_mission_node` 等 9 个 ELF）**全部是针对 Lyrical + gcc 15.2 + resolute ABI 编译的**，换 ROS 版本 = 全部重新链接，**没有源码就做不到**；② 厂商不会再给第二套镜像；③ 降级后 `apt` 源要换回 22.04，整机得重刷——**等于放弃现有能跑的状态**。 |
| 升级到更新的发行版（如后续 LTS） | 同上，而且更没验证过。 |
| 双系统并存（Lyrical + Humble） | 树莓派 4B 的 4 GB 卡装不下两套完整 ROS 2（每套 ~3 GB），且 DDS/domain 会互相干扰。 |

## 后果

**正面**
- 现有二进制**原样可用**（`sha256` 校验通过），不需要任何重新编译。
- 与厂商镜像保持一致，出问题能对得上厂商文档。

**负面 / 代价**
- **网上的 ROS 2 教程 90% 对不上**（Humble 的 launch/参数写法有差异，尤其 Nav2 1.5.x 的 MPPI 参数）。
- `apt` 源必须用 `resolute` 版本的 ROS 仓库（见 `docs/依赖清单.md` §1）。
- 遇到问题时"搜不到答案"是常态，只能读源码/读日志。

**缓解**
- `docs/依赖清单.md` 锁定了精确版本；
- `docs/竞赛笔记.md` §16 有"Lyrical 与 Humble 的差异"速查；
- 判断兼容性时以"车上实际能不能跑"为准，不以文档为准。

## 备注

如果将来必须换版本（例如厂商出新镜像），**这是新 ADR，不是修改本条**。
