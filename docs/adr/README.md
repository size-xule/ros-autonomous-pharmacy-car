# ADR · 架构决策记录

> **为什么要这个目录**：仓库里很多"看起来奇怪"的选择（为什么不用 Humble、为什么不重写任务层、
> 为什么航点不自动生成、为什么二进制也入库）其实都是**当时条件下的最优解**。
> 不写下来，接手的人会以为是疏忽，然后"好心"改坏。
>
> 格式：每条一个文件，`NNNN-英文短名.md`。**状态只有三种**：`已采纳` / `已废弃` / `已取代`。
>
> | 编号 | 决策 | 状态 |
> |---|---|---|
> | [0001](0001-lyrical-not-humble.md) | 用 ROS 2 **Lyrical**，不降级到 Humble | 已采纳 |
> | [0002](0002-task-layer-binary-only.md) | 任务层**不重写**，接受"只有二进制" | 已采纳 |
> | [0003](0003-manual-waypoints.md) | 航点**人工标定**，不做 SLAM 自动生成 | 已采纳 |
> | [0004](0004-car21-archive-only.md) | `.21` **只做归档**，不当第二台比赛车维护 | 已采纳 |
> | [0005](0005-vendor-binaries-in-repo.md) | 厂商二进制**入库**，而不是要求厂商给源码 | 已采纳 |
>
> 新增 ADR 时：复制任意一条的结构，编号 +1，**不要修改已采纳 ADR 的结论**（要推翻就新写一条，把旧的标 `已取代`）。

## 通用背景（5 条共用）

这个项目是**一支学生队在一次备赛周期内**做出来的，约束条件：

| 约束 | 具体 |
|---|---|
| 时间 | 备赛 ~3 个月，比赛后就要交接 |
| 人手 | 2 人（cxy / xl） |
| 硬件 | 厂商整机（EPRobot V2.3 / 树莓派 4B），不可换平台 |
| 软件 | 厂商给"能跑的镜像 + 二进制任务层"，源码只给了底盘驱动（Python）与下位机固件 |
| 目标 | **比赛拿分**优先，工程优雅其次 |

下面的每条 ADR 都是在这个前提下做的取舍。
