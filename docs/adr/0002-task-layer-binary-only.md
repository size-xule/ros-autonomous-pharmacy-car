# ADR-0002：任务层不重写，接受"只有二进制"

- **状态**：已采纳
- **日期**：2026-11
- **决策者**：cxy、xl

---

## 背景

比赛逻辑全在 `pharmacy_pkg` 里（`f1_mission_node` / `pharmacy_qr_node` / `pharmacy_board2_node` /
`judge_tcp_node` / `pharmacy_speech_node`，共 9 个 ELF）。厂商**只给了编译产物**，没给 `CMakeLists.txt`，
车上 `find / -name 'CMakeLists.txt' -path '*pharmacy*'` 也是空的（2026-11-13 实测）。

团队曾两次尝试"从 `.21` 的 SD 卡里捞源码"——**`.21` 的 `src/` 里同样只有 7 个第三方包，没有 `pharmacy_pkg`**。

## 决策

**不重写任务层。** 接受"二进制是唯一产物"，把可改范围**明确限定**为：

| 能改 | 不能改 |
|---|---|
| `mission_waypoints.yaml`（航点） | 任务流程（C→A→B 顺序、重试、播报时机） |
| `pharmacy.yaml`（裁判地址、超时、后端选择） | 二维码解码算法 |
| `goal_speed_limit.py`（限速表） | 裁判 JSON 字段与格式 |
| `nav2_params.yaml`（Nav2 参数） | 板二 OCR 的触发时机 |
| `competition.launch.py` 的启动参数 | 任何 `pharmacy_pkg` 内部逻辑 |
| systemd unit 的环境变量 | — |

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| **按行为逆推重写一份** | 任务层涉及：5 个节点、约 12 个话题、语音 77 段、裁判协议、板二三后端、4 种识别编码。**重写 ≈ 重做一个项目**，而比赛只剩几周。风险是"重写完还不如原来的"。 |
| **反编译 + 改二进制** | ① 违反本仓库红线；② `f1_mission_node` 2.5 MB、`-O2` 优化过的 C++，可读性极差；③ 改坏了无法回滚（没有源码就无法重建）。 |
| **找厂商要源码** | 已尝试，未获得（厂商视任务层为核心资产）。**这条仍然开放**：ADR 0005 里记了索取清单。 |
| 用 Python 重写"简化版任务" | 需要重做二维码解码 + 板二 OCR + 裁判协议 + 语音调度，等于新项目；且 Py 版在 Pi 上的时序精度不如 C++。 |

## 后果

**正面**
- 保住了**已验证可跑**的状态（这是比赛最值钱的东西）。
- 交接时不会有人因为"看不懂源码"而乱改。

**负面 / 代价**
- **任务层的行为只能通过文档描述**（`docs/竞赛笔记.md` §7 是从事件流/日志/参数反推的，不是读代码）。
- 出现"逻辑 bug"时**无法修**，只能绕过（改航点、改限速、改后端、改超时）。
- 新人容易误以为"改 YAML 就能改逻辑"，撞墙后才明白。

**缓解**
- `docs/学弟上手路径.md` §4 明确列出"能改 / 改不了"两栏；
- `lib/pharmacy_pkg/BUILD_INFO.md` 记录"构建命令未知 + 4 项索取清单"；
- 每改一个 YAML 都要**实车验证**，因为看不到代码。
