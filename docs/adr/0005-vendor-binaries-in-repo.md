# ADR-0005：厂商二进制入库，而不是要求厂商给源码

- **状态**：已采纳
- **日期**：2026-11
- **决策者**：cxy、xl

---

## 背景

仓库里有大量**非本项目原创**的材料：

| 材料 | 大小 | 来源 |
|---|---:|---|
| 任务层 9 个 ELF（`f1_mission_node` 等） | 14 MB | EPRobot 编译产物 |
| Orbbec OpenNI2 SDK | 2.7 MB | 奥比中光 |
| STM32 固件源码（2 个 `.7z`） | 24 MB | EPRobot |
| 原理图 + 协议表 | 2.1 MB | EPRobot |
| PP-OCRv6 模型 | 6.1 MB | PaddleOCR |

把这些放进一个**公开仓库**，是有法律风险的（见 `NOTICE.md`）。

## 决策

**二进制/厂商材料入库**，同时：
1. 写清归属（`NOTICE.md` 逐项列表）；
2. 明确"仅限学习与竞赛复现，不商用、不再分发牟利"；
3. 声明"权利人可要求移除，我们会立即处理"；
4. 仓库当前设为 **public**（作者授权），**如权利人异议可一键转 private**。

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| **只放 md5，让使用者找厂商要** | ① 厂商不会给个人（我们试过）；② 没有这 9 个 ELF，**仓库就完全跑不起来**——那这份仓库作为"可恢复镜像"就没有意义了；③ 比赛现场没有网络下载的条件。 |
| 放进 Git LFS / Release 附件 | ① 本项目没有 LFS 额度，24+14 MB 会超；② Release 附件在"下载 ZIP"流程里拿不到，而 `README.md` 的主打用法就是 Download ZIP。 |
| 只放源码，二进制让使用者自己编译 | **没有源码**（ADR-0002）。 |
| 全部私有 | 交接/给学弟看就不方便了。作者选了 public，风险已告知（见 `NOTICE.md` §使用限制 与 `SECRETS.md`）。 |

## 后果

**正面**
- **仓库是自包含的**：Download ZIP → 铺到新车 → 能跑（只差密码与航点）。
- 交接时不依赖厂商是否配合。

**负面 / 代价**
- 有版权风险：厂商/奥比中光理论上可以要求下架。
- 仓库体积 **85 MB**，clone 慢（但可接受：一次性的）。
- 二进制无源码 → 出问题只能绕过（ADR-0002）。

**缓解**
- `NOTICE.md` 明确逐项归属 + 非商用限制 + 可移除承诺；
- 自己的文档/脚本用 **CC BY-SA 4.0 / MIT** 单独声明（`LICENSE` / `LICENSE-DOCS`），
  与厂商材料**在许可上分开**；
- `SECRETS.md` 保证不带任何真实凭据，"下架"时不需要清理历史。

## 索取清单（仍然开放）

万一将来能拿到授权/源码，优先顺序：

1. `pharmacy_pkg` 的 **colcon 工程**（`CMakeLists.txt` + `src/`）——最有价值，能解锁 ADR-0002；

3. `eprobot_base_cpp` 的 `.cpp` 实现（现在只有头文件 + 二进制）；
4. 奥比中光对 SDK 再分发的书面许可。
