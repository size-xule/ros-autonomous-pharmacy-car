# ADR-0003：航点人工标定，不做 SLAM 自动生成

- **状态**：已采纳
- **日期**：2026-11
- **决策者**：cxy、xl

---

## 背景

比赛要求车在固定场地上反复停到**同一批位置**（A/B/C 取样窗口、board1、board2、4 个送样窗口、home），
每个位置还要求特定**朝向**，并且必须"整车进框、停稳"。

理论上可以：
- 建一张高精度地图，然后在地图上点选坐标；
- 或者用"语义地图/目标检测"自动推断窗口位置。

## 决策

**航点由人工在现场标定**，写进 `mission_waypoints.yaml`，**不做自动生成**。

## 被否决的方案

| 方案 | 为什么否决 |
|---|---|
| **SLAM 建图后在地图上点** | ① 地图精度受雷达（M10，10 Hz，100 ms 运动畸变）限制，**地图上的点是"雷达看到的墙"，不是"车该停的位置"**；② 点选得到的是 `map` 坐标，但**车能不能停进去**取决于车体半对角 0.186 m 与货架余量，这只能现场量；③ 建图与导航互斥（`eprobot-slam`/`eprobot-carto` 与 `eprobot-nav` 不能同开），来回切换成本高。 |
| **用二维码/文字牌做视觉伺服自动停车** | ① 需要标定相机外参（本车**没有标定文件**，见 `CALIBRATION.md`）；② 视觉伺服在 ±10 cm 的精度上不如直接给坐标稳；③ 增加了失败模式（识别不到就停不下来）。 |
| **从录像/人工示教回放轨迹** | ① 阿克曼底盘的轨迹回放对初始位姿极敏感，1 cm 偏差会累积；② 回放无法处理"上一圈停歪了"的情况（没有闭环）。 |
| 用 Nav2 的 `waypoint_follower` 批量跑 | 这个**已经在用**（航点交给 Nav2），但**坐标本身仍然要人工标**——两件事不冲突。 |

## 后果

**正面**
- 每个点都能**量出余量**，直接对应"会不会蹭墙"这个真实风险。
- 换场地时只需重标 11 个点，**不需要重建整张地图**（地图可以复用同一场地的）。
- 标定过程简单到"一个学弟 + 一把卷尺 + RViz"就能做（见 `docs/航点标定手册.md`）。

**负面 / 代价**
- **坐标不可跨车复用**。实测：`.21` 与 `.22` 同一套代码，`board2` 差 **0.72 m**、`board1` 差 10 cm。
  换车必须重标，这是硬成本。
- 标定质量依赖人（量余量、量朝向），**没有自动化校验**——所以我们补了一个偏差校验脚本
  （`docs/航点标定手册.md` §2.5，打印"当前位姿 vs 目标点"的距离与角度差）。
- 场地布置一变（货架挪了 5 cm），坐标就得重来。

**缓解**
- `docs/航点标定手册.md` 给了完整流程 + 记录模板 + 校验命令；
- `cars/car22/README.md` §8 顶部红框警告"不可跨车复用"；
- 每个点都要求记录"实测余量"，余量 < 0.19 m 的点标记为待优化。

## 备注

如果将来要做自动生成，前提是：**先有相机标定 + 一张厘米级地图 + 一个能验证余量的仿真环境**。
三条现在都没有，所以这条 ADR 短期内不会被推翻。
