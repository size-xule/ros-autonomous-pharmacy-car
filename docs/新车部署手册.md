# 新车部署手册（把本仓库铺到一台新车上）

> 目标：一台**同型号、同镜像**的新车（EPRobot / Pi4B / Ubuntu 26.04 + ROS 2 Lyrical），从零跑到能完成一圈。
> 适用：换车、重刷系统、卡损坏重建。
> 前置阅读：`docs/竞赛笔记.md` 的 §12（一天清单）与 §17.3（未解问题）。

---

## 0. 先确认前提（不满足就别往下走）

| # | 前提 | 怎么验 |
|---|---|---|
| 1 | 新车的 **ROS 2 Lyrical 已装** | `ls -d /opt/ros/lyrical` |
| 2 | 有 `/opt/eprobot_ws` 且能 source | `source /opt/eprobot_ws/install/setup.bash` 不报错 |
| 3 | 底盘能出 `/odom`（车上跑的是 **`eprobot_base_cpp`**：二进制在 `rootfs/opt/eprobot_ws/install/eprobot_base_cpp/`，源码缺失） | `ros2 topic echo --once /odom` |
| 4 | 相机是 **Astra S**（或同款无 UVC） | `lsusb \| grep 2bc5` → `2bc5:0402` |
| 5 | 有 `python3`、`colcon`、`sshpass`（主机侧） | `python3 -V; colcon version-check` |
| 6 | 新车的 IP/账号与 `.22` **不同**（避免撞车） | 见 §1.2 |

> 如果新车是 **Astra Pro HD（有 UVC）**，跳过 OpenNI2 + relay 这一整套，直接用 `v4l2_camera` 出 `mono8` 即可（`.21` 就是这种）。
> 本手册只覆盖 **Astra S** 这条链。

## 1. 准备

### 1.1 拿到仓库

```bash
# 在主机（WSL / Linux）上，不要直接在车上 clone（车上没有 git 凭据）
git clone https://github.com/size-xule/ros-autonomous-pharmacy-car.git
cd ros-autonomous-pharmacy-car
```

### 1.2 改掉"会撞车"的三处

| 位置 | 改什么 |
|---|---|
| `cars/car22/rootfs/etc/netplan/01-wlan0.yaml` | `addresses` 改新车 IP；`access-points` 改现场热点；**`password: "WIFI_PASSWORD_HERE"` 必须填真值**（仓库里已脱敏） |
| `cars/car22/rootfs/etc/netplan/50-cloud-init.yaml` | **同上**（两个文件都要改，否则后读的覆盖前面的，见竞赛笔记 §18.2） |
| `cars/car22/rootfs/opt/eprobot_ws/install/pharmacy_pkg/share/pharmacy_pkg/config/pharmacy.yaml` | `judge_tcp.host` 改成**现场裁判机实际 IP**；`car_id` 按需 |

> ⚠️ 仓库里的 WiFi 密码是占位符 `WIFI_PASSWORD_HERE`（凭据不入库），铺之前一定改掉，否则新车连不上热点、你只能靠网线救。
> 
> ⚠️ **多车同网必须分 `ROS_DOMAIN_ID`**（`.22` 是 `1`）。新车用 `2`：要改 15 个 unit 的 `Environment=`、`iscc.conf`、主机侧环境变量。**不改会出现"两台车的 /odom 串在一起、位姿乱跳"**（竞赛笔记 §18.4）。

### 1.3 确认能连上新车

```bash
ping <新车IP>
ssh <user>@<新车IP> 'hostname; . /etc/os-release; echo $PRETTY_NAME; ls -d /opt/ros/*'
```

## 2. 一键铺（推荐）

```bash
# ① 干跑：只打印要做什么，不写任何东西
bash install/apply_to_car22.sh --host <新车IP> --user <账号> --dry-run

# ② 真干：会先把冲突文件备份到 ~/.backup_<时间戳>/
bash install/apply_to_car22.sh --host <新车IP> --user <账号> --yes

# ③ 编译需要 build 的包
bash install/apply_to_car22.sh --host <新车IP> --user <账号> --build

# ④ 建两个 .so 软链（脚本会自动做，这里列出以便核对）
#    /opt/oni2-orbbec/libOpenNI2.so.0 -> libOpenNI2.so
#    /opt/oni2-orbbec/libOpenNI2.so.0.0 -> libOpenNI2.so
```

脚本做的事（按顺序）：

1. 校验目标（`/opt/ros/lyrical`、`/opt/eprobot_ws` 存在；不是 `.22` 本人）
2. 备份将被覆盖的路径 → `~/.backup_<ts>/`
3. `cp -a rootfs/* → /`（保留权限/属主以外的所有属性）
4. 修正属主（`keyuan22` 或 `--user` 指定）
5. 建 `libOpenNI2.so.*` 软链
6. `systemctl daemon-reload`，`enable` 基础 5 个 unit（**不 start**）
7. `udevadm control --reload-rules && udevadm trigger`
8. `--build` 时：`colcon build`（`src/opt_eprobot_ws_src` → `/opt/eprobot_ws`；`src/relay_ws` → `~/relay_ws`）
9. 打印"手动检查清单"

**不会做的事**（必须人工确认）：起服务、改 IP、标航点、连裁判。

## 3. 手动分步（脚本失败时照这个做）

### 3.1 拷成品

```bash
# 在主机上，把 rootfs 推过去
rsync -av --progress cars/car22/rootfs/ <user>@<IP>:/tmp/car22-rootfs/

# 在车上
sudo cp -a /tmp/car22-rootfs/opt/.        /opt/
sudo cp -a /tmp/car22-rootfs/home/keyuan22/. /home/keyuan22/
sudo cp -a /tmp/car22-rootfs/etc/systemd/system/. /etc/systemd/system/
sudo cp -a /tmp/car22-rootfs/etc/default/.    /etc/default/
sudo cp -a /tmp/car22-rootfs/etc/netplan/.    /etc/netplan/
sudo cp -a /tmp/car22-rootfs/etc/udev/rules.d/. /etc/udev/rules.d/
sudo cp -a /tmp/car22-rootfs/etc/chrony/.     /etc/chrony/
sudo cp -a /tmp/car22-rootfs/usr/local/bin/.  /usr/local/bin/
sudo chmod +x /usr/local/bin/*
```

### 3.2 建软链

```bash
cd /opt/oni2-orbbec
sudo ln -sf libOpenNI2.so libOpenNI2.so.0
sudo ln -sf libOpenNI2.so libOpenNI2.so.0.0
sudo ldconfig
```

### 3.3 编译源码

```bash
# lslidar / serial / yesense（eprobot_base 是 Python 参考实现，可选）
cp -a src/opt_eprobot_ws_src/* /opt/eprobot_ws/src/
cd /opt/eprobot_ws
source /opt/ros/lyrical/setup.bash
colcon build --symlink-install --packages-select \
  serial_ros2 yesense_interface yesense_std_ros2 lslidar_ros2
source install/setup.bash

# C++ mono8 relay
mkdir -p ~/relay_ws/src && cp -a src/relay_ws/mono8_relay ~/relay_ws/src/
cd ~/relay_ws && source /opt/ros/lyrical/setup.bash
colcon build --packages-select mono8_relay
```

> 包名以 `package.xml` 里的 `<name>` 为准；`colcon list` 可以看全。
>
> ⚠️ **不要 `--packages-select eprobot_base_cpp`**：这个包**没有源码**（`src/` 里不存在），
> 车上用的是从 `rootfs/.../install/eprobot_base_cpp/` 铺过去的**二进制 + 头文件**。
> `src/.../eprobot_base/` 是**另一套**（Python 参考实现），默认不参与运行。

### 3.4 装 OCR 运行时（`runtime_arm64` 没入库）

```bash
cd ~/board2_ocr
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt         # onnxruntime / rapidocr / opencv 等
# 然后把 run_worker.sh 里的解释器路径改成 .venv/bin/python
```

> 如果旧车还在，最快是直接把 `~/board2_ocr/runtime_arm64` 整目录拷过来（276 MB）。

### 3.5 启用服务（先不 start）

```bash
sudo systemctl daemon-reload
sudo systemctl enable eprobot-base eprobot-imu openni2-camera mono8-relay scan-viz
sudo udevadm control --reload-rules && sudo udevadm trigger
```

### 3.6 验收（**六项全过再谈跑**）

```bash
export ROS_DOMAIN_ID=1 FASTDDS_BUILTIN_TRANSPORTS=UDPv4
source /opt/ros/lyrical/setup.bash && source /opt/eprobot_ws/install/setup.bash

ros2 topic hz /odom                                  # ~50 Hz
ros2 topic hz /scan                                  # ~10 Hz
ros2 topic echo --once /imu/data                     # 有四元数
ros2 topic echo --once --qos-reliability best_effort /battery_state   # ≥11 V
ros2 topic hz /camera/rgb/image_raw --qos-reliability best_effort     # 7~10 Hz
journalctl -u eprobot-nav | grep 'Managed nodes are active'           # 起 nav 后才有
```

### 3.7 起车

```bash
iscc version && iscc kill && iscc pre
iscc gray          # 看得到画面 → 相机 OK
iscc rviz2         # 车得在地图上的正确位置（激光贴墙）
iscc start         # ★ 车会动，先清场
```

## 4. 换车必做：重新标航点

**这是最容易漏、也最容易导致"跑起来但跑不对"的一步。**

坐标是"上一辆车 + 上一块场地 + 上一次停车姿态"下量出来的。换车后：

1. 把车推到起点，确认 `home` 就是地图原点、车头朝 +x。
2. RViz 里用 **2D Pose Estimate** 对齐激光与墙。
3. 逐点开到位置，用 `/amcl_pose`（或 RViz）读出 `x y yaw`，填进 `mission_waypoints.yaml`。
4. **每个点都要量"到墙/货架的余量"**，必须 > 车体半对角（`0.30×0.22` → 0.186 m；ROS 1 车是 0.182 m）。
5. 改完 `sudo systemctl restart eprobot-nav`（或重跑 mission），并**立刻 git 提交**。

> 判断"点位能不能进"的最快方法：在 RViz 里把 `inflation_radius 0.28` 的膨胀层打开，看目标点是否落在"深色禁行区"外。

## 5. 常见失败与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `iscc pre` 卡 `waiting for /odom` | 底盘没起 / 串口被占 / domain 不对 | `iscc status`；`systemctl status eprobot-base`；查 `ROS_DOMAIN_ID` |
| `failed to claim usb interface: BUSY` | 厂商进程 `orbbec_as` 占着相机 | `pkill -f orbbec_as`；或 USB unbind/bind（`iscc-usb-reset`） |
| `Image buffer is corrupt. Size is 371790` | 用了无效的 `color_mode` 参数 | 删掉该参数 |
| `/camera/rgb/image_raw` 没数据 | relay 没起 / 编码不支持 | `systemctl status mono8-relay`；`ros2 topic echo --once /camera/color/image_raw` 看上游 |
| `QR scan: candidates=0` 一直刷 | 图像不是 mono8 / 码太小 / 过曝 | 查 encoding；车再近 10 cm；`iscc gray` 里降曝光 |
| 板二永远说"等 8 秒" | `board2_backend` 被改成 `fixed`/`template` | 去掉覆盖参数，恢复 `rapidocr` |
| 车卡住不动 | 电池低 / 目标不可达 / 定位飘 | 先看电压；再量余量；RViz 看位姿 |
| 裁判没数据 | 软件没开 / IP 不对 / `judge_tcp` 没起 | `nc -zv <裁判IP> 8888`；改 `pharmacy.yaml` |
| 重启后 unit 不活 | 没 `enable` 或 `daemon-reload` 没做 | §3.5 |
