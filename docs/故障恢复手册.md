# 故障恢复手册

> **按"现象"组织**，不按模块。出问题时先找你的现象，照"排查命令"逐条敲，别猜。
> 日志片段均为**脱敏后的真实输出**（密码/IP 做过处理）。
>
> 配套：[`unit依赖关系.md`](unit依赖关系.md)（谁挂了会怎样）、[`../tools/probes/README.md`](../tools/probes/README.md)（只读探针）。

---

## 0. 万能前三步（90% 的问题在这三步内定位）

```bash
# ① 服务层：该起的起了吗
iscc status
# 或
systemctl list-units --type=service --state=running | grep -E 'eprobot|lslidar|camera|relay|scan-viz'

# ② 日志层：最近 100 行有没有红
journalctl -u <unit> -n 100 --no-pager

# ③ 数据层：话题在不在、有没有帧
ros2 topic list | sort
ros2 topic hz /odom &          # 5 秒后 Ctrl-C
```

> **判据顺序**：服务没起 → 看 journal；服务起了没数据 → 看 topic；有 topic 没帧 → 看发布者进程。

## 1. 车"起不来"

### 1.1 完全没反应（连不上、无灯）

| 检查 | 命令 | 判据 |
|---|---|---|
| 供电 | 看底盘电源灯 / 万用表 | 电池 ≥ 11 V |
| 是否在启动中 | `ping <IP>` 连续 30 s | 前 1 分钟 ping 不通是正常的（cloud-init 慢） |
| SD 卡在不在 | 拆开看卡槽 | 卡没插 = 起不来（`.21` 就是这样） |
| HDMI 输出 | 接显示器 | 卡在 `cloud-init` 或 kernel panic 会停在黑屏/滚动日志 |

**真实片段**（欠压重启，`journalctl -b -1` 末尾**没有** shutdown 记录）：
```
-- Reboot --
Nov 05 14:22:31 EPRobot2 systemd[1]: Started ISCC_CAR ROS 2 chassis driver.
```
→ 上次是**直接掉电**（不是正常关机）。查 `vcgencmd get_throttled`（`0x50005` = 正在欠压）。

### 1.2 ping 得通但 SSH 不通

```bash
nc -zv <IP> 22
ssh -v <账号>@<IP>          # 看卡在哪一步
```
| 现象 | 原因 | 修 |
|---|---|---|
| `Connection refused` | sshd 没起 / 端口改了 | 本机登录 `systemctl status ssh` |
| `Permission denied` | 账号或密码错 | 注意 `.22` 是 `keyuan22`、`.21` 是 `ubuntu` |
| 超时 | 防火墙 / 路由 | `ip route` 看网关是不是 `.1` |

### 1.3 SSH 通了但只有 base 一个 unit

**这是正常的**（`iscc kill` 之后就是这状态）。`eprobot-nav` / `lslidar` / `eprobot-pharmacy` 都是 `disabled`，靠 `iscc pre` 拉起。

## 2. 某个 unit 挂了

> 完整对照表见 [`unit依赖关系.md`](unit依赖关系.md) §3。这里只列**最高频**的四个。

### 2.1 `eprobot-base` 起不来（没有 `/odom`）

```
● eprobot-base.service - ISCC_CAR ROS 2 chassis driver
     Active: activating (auto-restart) (Result: exit-code)
    Process: 1234 ExecStart=... (code=exited, status=1/FAILURE)
```
```bash
fuser -v /dev/EPRobot_base          # 有没有别的进程占着
ls -l /dev/EPRobot_base             # 软链在不在（udev）
journalctl -u eprobot-base -n 50 | grep -iE 'serial|permission|open'
```
| 原因 | 判据 | 修 |
|---|---|---|
| 串口被占（双实例） | `fuser` 显示两个 PID | `pkill -f eprobot_base` 后 `systemctl restart` |
| 设备不存在 | `ls` 报 No such file | 查 `99-eprobot-base.rules`；`udevadm trigger` |
| 权限 | `Permission denied` | 用户在 `dialout` 组：`sudo usermod -aG dialout keyuan22`，**重登** |
| 蓝牙占了 ttyAMA0 | `/dev/EPRobot_base -> ttyS0` | `config.txt` 加 `dtoverlay=disable-bt` |

### 2.2 `openni2-camera` 反复重启（相机不出图）

```
Nov 13 21:05:12 EPRobot2 openni2-camera[2101]: [Error] [OpenNI2] Failed to open device
Nov 13 21:05:12 EPRobot2 systemd[1]: openni2-camera.service: Main process exited, code=exited, status=1/FAILURE
```
```bash
lsusb | grep 2bc5                 # 相机在不在（2bc5:0402）
pkill -f orbbec_as                # 厂商进程占 USB
iscc-usb-reset                    # 或 /usr/local/bin/iscc-usb-reset
```
**最常见原因**：厂商的 `orbbec_as` 进程占着 USB 接口 → `failed to claim usb interface: BUSY`。
**次常见**：加了无效的 `color_mode` 参数 → 每帧都坏（`Image buffer is corrupt. Size is 371790`）。

### 2.3 `mono8-relay` 起来了但 `/camera/rgb/image_raw` 没帧

```bash
ros2 topic hz /camera/color/image_raw       # 上游有吗？
```
- 上游**有** → relay 的问题：
  ```bash
  journalctl -u mono8-relay -n 50
  # 常见：cv_bridge 转换失败 / 上游编码不是 rgb8
  ```
- 上游**没有** → 回到 2.2（相机问题），relay 是无辜的。

### 2.4 `eprobot-nav` 起不来

```
[ERROR] [nav2_bringup]: Failed to bring up all requested nodes. Aborting bringup.
```
| 原因 | 判据 | 修 |
|---|---|---|
| **`/odom` 还没有帧就起了 nav** | `ros2 topic hz /odom` 空 | **先等 odom，再 `restart eprobot-nav`**（铁律 1） |
| 没有 `/scan` | `ros2 topic hz /scan` 空 | 先修雷达（§4） |
| TF 冲突（两个 `odom→base_link`） | `ros2 run tf2_tools view_frames` | 关掉重复的（`publish_tf` / EKF 二选一） |
| 地图文件不存在 | 日志里有 `map.yaml` 路径 | 检查 `~/maps/iscc_3.yaml` |

## 3. 串口不通

```bash
ls -l /dev/EPRobot_base          # 存在？
sudo fuser -v /dev/EPRobot_base  # 被谁占？
groups | grep dialout            # 有组？
stty -F /dev/EPRobot_base -a     # 参数对不对（115200 8N1）
```
| 现象 | 原因 | 修 |
|---|---|---|
| 设备文件不存在 | udev 没匹配 / 串口没启用 | `udevadm test /sys/class/tty/ttyAMA0`；检查 `config.txt` 的 `enable_uart=1` |
| `Device or resource busy` | 两个进程抢 | `pkill -f 'eprobot_base\|art_racecar'` 后重启 unit |
| 能开但收不到帧 | 波特率/线序 / MCU 没上电 | 用 `ros2 topic echo /odom` 看；MCU 的 OLED 是否亮 |

**验证串口活着的土办法**（不动固件）：
```bash
sudo timeout 3 cat /dev/EPRobot_base | xxd | head     # 应该有 5A 开头的帧
```

## 4. 雷达没数据（`/scan` 空）

```bash
systemctl status lslidar
ros2 topic hz /scan
ros2 topic info -v /scan | grep 'Publisher count'     # 2 = 双实例
ls -l /dev/ttyUSB*
/usr/local/bin/lslidar-ctl status
```
| 现象 | 原因 | 修 |
|---|---|---|
| 节点在、hz=0 | 电机没转 | `lslidar-ctl start`；听雷达有没有转 |
| `Publisher count: 2` | 双实例 | `pkill -f lslidar_driver_node` 后重启 unit |
| `/dev/ttyUSB0` 不存在 | USB 松 / 供电不足 | 换口；雷达单独供电 |
| 有 `/scan` 但 RViz 里"整图旋转" | 时间戳错误（整帧用第一束的时间） | 已知限制，高速转弯时 8~12° 畸变，不是故障 |

## 5. IMU 没数据（`/imu/data` 空）

```bash
ls -l /dev/EPRobot_imu          # 软链
udevadm info -a -n /dev/ttyACM0 | grep -E 'idVendor|idProduct|serial'
systemctl status eprobot-imu
```
| 现象 | 原因 | 修 |
|---|---|---|
| `/dev/EPRobot_imu` 不存在 | **序列号不匹配**（换过 IMU） | 改 `99-eprobot-h30.rules`（见 udev README §1.2） |
| 设备在但没数据 | 波特率/线序 | `yesense_config.yaml` 里应是 **460800** |
| 角速度**恒为 0**（但四元数在动） | **正常**：陀螺量化 0.061°/s，低速时精确输出 0 | 不需要修（见 §0.2 第 5 条） |

## 6. 定位飘 / 车在 RViz 上乱跳

| 现象 | 先查 | 命令 |
|---|---|---|
| 车模在墙上穿来穿去 | 初始位姿 | RViz 2D Pose Estimate 重对 |
| 走着走着整体偏移 | `/odom` 与 `/scan` 不匹配 | 低速直行 2 m，量实际距离与 odom 差 |
| **两台车数据串台** | `ROS_DOMAIN_ID` | `ros2 topic info /odom \| grep 'Publisher count'` → 2 就是串了 |
| 转弯时方向反 | `yaw_sign` / `gyro_sign` | 低速左转，看 odom yaw 是否增大 |
| RViz 空白但窗口正常 | **时钟差** | `date` 与主机对比；差 >1 s 会让 tf2 丢帧 |

## 7. 二维码识别失败（`QR scan: candidates=0` 一直刷）

```bash
ros2 topic hz /camera/rgb/image_raw --qos-reliability best_effort
ros2 topic echo --once /camera/rgb/image_raw --field encoding      # 必须 mono8
iscc gray                                                          # 看画面
journalctl -u eprobot-pharmacy -n 50 | grep -i 'QR scan'
```
| 原因 | 判据 | 修 |
|---|---|---|
| 图像不是 **mono8** | `encoding: rgb8` | 走 `mono8-relay`，别直连相机 |
| 码太小 | 画面里 < 55 px | 车再近 10 cm；或改 `board1` 停车点 |
| 过曝 | 码面一片白 | `iscc camtune` 扫曝光；降 `exposure` |
| 停歪了 | 码不在画面内 | 重标 `board1` |
| 相机链断 | 无帧 | 回到 §2.2 / §2.3 |

## 8. 板二识别失败（一直 `UNKNOWN` / 一直"等 8 秒"）

```bash
journalctl -u eprobot-pharmacy | grep -iE 'board2|ocr'
ls ~/board2_ocr/runtime_arm64 >/dev/null && echo runtime-ok
echo <图片路径> | PYTHONPATH=~/board2_ocr/runtime_arm64 /usr/bin/python3 ~/board2_ocr/board2_ocr_worker.py
```
| 现象 | 原因 | 修 |
|---|---|---|
| `ModuleNotFoundError: rapidocr` | 运行时没装 | 见 `runtime/README.md` |
| 永远 `BUSY_8` | 后端被改成 `fixed`/`template`（只有 OCR 后端能出 `BUSY_5..10`） | 去掉 `board2_backend` 覆盖，恢复 `rapidocr` |
| `UNKNOWN` | 过曝/太远/牌面反光 | 退后 10 cm；调曝光；换 `fixed` 兜底 |
| 启动 20 s 才就绪 | 模型冷加载（正常） | 确认 `startup_timeout: 15.0` 够大 |

## 9. 语音不响

```bash
ls /home/keyuan22/board2_ocr/../../*/audio/competition/*.wav | wc -l   # 应 77
aplay -l                                    # 有没有声卡
groups | grep audio                         # 用户在 audio 组？

```
| 原因 | 修 |
|---|---|
| 不在 `audio` 组 | `sudo usermod -aG audio keyuan22`，**重登** |
| 混音器静音 | `amixer -c 0 sset PCM 100% unmute`（unit 的 `ExecStartPre` 已做） |
| wav 缺失/名字不匹配 | `speech_manifest.json` 与文件名强绑定，少一个就播不出 |

## 10. 裁判没数据

```bash
nc -zv <裁判IP> 8888
grep host /opt/eprobot_ws/install/pharmacy_pkg/share/pharmacy_pkg/config/pharmacy.yaml
ss -tnp | grep 8888            # ESTAB = 连上了
journalctl -u eprobot-pharmacy | grep -i judge
```
**最常见原因**：`pharmacy.yaml` 写的是 `10.211.121.38`，现场裁判机是别的 IP。
→ 改 `judge_tcp.host` 为现场实际 IP，`sudo systemctl restart eprobot-pharmacy`。

## 11. 车不动 / 跑一半停

| 现象 | 先查 | 说明 |
|---|---|---|
| `iscc start` 后完全不动 | 是否真的起了 mission | `ros2 node list \| grep nav_pharmacy` |
| 走到一半停住 | 电池 | 低于 11 V 会"各项都失败" |
| 报 `Failed to make progress` | 余量/膨胀 | 目标点太靠墙；放宽判据或挪点 |
| 一直倒车 | 卡住恢复行为 | `behavior_server` 的 recoveries；看是否真卡住 |
| 速度很慢 | 限速表 | `goal_speed_limit.py` 的 `C>B`/`A>B` |
| 原地打转 | 目标 yaw 与来向差太大 | 改 yaw 或加过渡点（`ac_transit`） |

## 12. 系统级

### 12.1 Fast DDS 共享内存泄漏

```bash
ls /dev/shm | grep -c fastdds        # 两位数以上就是泄漏
```
**修**：`iscc kill`（会清 `/dev/shm/fastdds_*`）。**根治**：unit 里加 `FASTDDS_BUILTIN_TRANSPORTS=UDPv4`。

### 12.2 时钟跳变（无 RTC）

```bash
timedatectl; chronyc tracking
```
现象：RViz 反复 `Message Filter dropping message ... queue is full`。
修：`chrony` 已配阿里云 NTP；上车先 `sudo systemctl restart chrony`。

### 12.3 磁盘满

```bash
df -h /
du -sh ~/* | sort -h | tail
```
常见占用：`~/bags`、`/var/log/journal`、`evidence/`。
修：`sudo journalctl --vacuum-size=200M`；删旧 bag。

### 12.4 CPU 被抢（车卡顿、Nav2 超时）

```bash
ps -eo pcpu,comm --sort=-pcpu | head -6
```
不该出现：`unattended-upgrade`、`dpkg`、`apt`、`updatedb`。
修：`sudo systemctl stop unattended-upgrades`；`.22` 可照搬 `.21` 的 `cpu-performance.service`。

## 13. 比赛现场 5 分钟应急（贴在工具箱上）

```
① 电压 < 11 V → 换电池（不要"再跑一圈看看"）
② iscc status 看 unit → 缺哪个就 systemctl restart 哪个
③ iscc kill && iscc pre（90 秒）→ 六项验收
④ 相机没图 → iscc gray；黑屏就 pkill -f orbbec_as + iscc-usb-reset + restart
⑤ 裁判没数据 → nc -zv <IP> 8888；改 pharmacy.yaml 的 host
⑥ 都不行 → 本机登录，journalctl -u <unit> -n 50，拍照发群里
```

## 14. 日志位置总表

| 内容 | 位置 / 命令 |
|---|---|
| 某个 unit | `journalctl -u <unit> -n 100 --no-pager` |
| 本次开机全部 | `journalctl -b --no-pager` |
| 上次开机（查掉电） | `journalctl -b -1 --no-pager \| tail -50` |
| 任务事件流 | `~/.log/pharmacy/mission.jsonl`（或车上 `/home/keyuan22/...`） |
| 二维码事件 | `~/.log/pharmacy/qr.jsonl` |
| 导航 | `journalctl -u eprobot-nav` |
| 相机 | `journalctl -u openni2-camera mono8-relay` |
| 内核/欠压 | `dmesg -T \| tail -50`；`vcgencmd get_throttled` |
| 系统重启原因 | `last -x \| head` |
